- The ENKOP master is the Cloudflare Worker `enkop` backed by ENKOP's own Supabase project (`enkop`, eu-west-2): Postgres reached through the Hyperdrive binding `HYPERDRIVE` (query caching disabled so every read sees the latest write) (`pg` driver, src/server/backend/pg.ts behind the D1-style `prepare/bind/all/first/run/batch` interface) and media in its private `property-media` Storage bucket (ENKOP_SUPABASE_URL / ENKOP_SUPABASE_SERVICE_KEY). It is the single source of truth; Lovable Cloud is a mirror kept in sync automatically. The old D1 `enkop-db` and KV namespace are kept read-only as a rollback. Public catalogue reads published records and enquiries are written through validated server functions so the presentation stays separate from data access.
- Property imagery is mapped from local editorial assets by image key; illustrative listings are explicitly labelled until genuine inventory is supplied.
- The homepage hero video files live in public/videos/scenes (MP4, WebM and a poster per scene) because the site is also deployed to Vercel, where Lovable's /__l5e asset URLs return 404; never point hero media at /__l5e or .asset.json URLs.
- Property tour videos are generated server-side via AI Gateway /v1/videos, polled by the admin client, and copied into the private property-media bucket on completion because gateway downloads expire.
- Homepage hero scenes come from the homepage_slides table; the public loader signs only active slide paths server-side. The current hero is a single scene, the ENKOP landing walkthrough (`homepage/enkop-landing.mp4`, served from public/videos/scenes/enkop-landing{,-720}.mp4 as a seamless loop: 1080p on wide screens, 720p on phones); it is also the built-in fallback. The earlier three scenes stay in storage and public/ but their slides are inactive.
- Matching homepage fallback images use a browser-captured video frame and an admin-verified streaming AI Gateway image-edit route; only an explicitly approved final image is stored and assigned to the scene.
- Page transitions use a persistent root-level curtain with an in-memory public-navigation counter alternating seasonal effects and page flips; router lifecycle events drive the non-blocking reveal, native snapshot transitions stay disabled, and reduced motion, same-page and admin navigation bypass without advancing the counter.
- Page flips capture an inert, transient outgoing-page DOM image across curved CSS-3D strips; remove snapshots on completion and keep all snapshot work browser-only to preserve navigation and SSR safety.
- Autumn navigation uses a preloaded photographic botanical sprite atlas, cached soft-focus variants and deterministic canvas wind paths; skip the effect if textures are unavailable rather than rendering illustrated substitutes, keeping navigation immediate and per-frame rendering filter-free.
- Homepage playback uses path-keyed MP4/WebM variants from public/videos/scenes for existing footage, preloads only the current and next scenes, and reveals videos only after playback starts; changed upload paths keep their own footage.
- Built-in footage preserves source texture without denoising, with restrained sharpening and bounded compression: wide screens select upscaled 4K and phones select HD via media-qualified sources, retaining original codec fallbacks and never substituting enhanced built-ins for new uploads.
- Phone layouts use bounded grid tracks, readable form fields and safe-area-aware scrollable overlays; pointer-driven tilt is reserved for fine hover-capable pointers to keep touch scrolling stable.
- Privileged work (media signing, enquiry insert + WhatsApp alert, AI Gateway) goes through src/integrations/supabase/privileged.server.ts: direct when managed keys exist, otherwise via the secret-authenticated /api/public/enkop-bridge route on Lovable hosting (ENKOP_BRIDGE_SECRET, optional ENKOP_BRIDGE_URL) so non-Lovable hosts work without holding managed keys.
- Data access goes through `getBackend()` (public reads, media signing, enquiries) and `getMaster()` / the `requireAdmin` middleware in src/lib/require-admin.ts (admin reads and writes) from src/server/backend. Never query Supabase directly from route or `*.functions.ts` code: on the master those calls would read the stale mirror.
- Master writes go through `MasterStore` (`upsert`/`update`/`remove`/`run`). The `enkop_outbox()` trigger on every content table queues each insert/update/delete (including dashboard edits) in the master `outbox` in the same transaction; media and alerts are queued by code. The outbox is drained to the mirror via the bridge `mirror/*` routes after each write, on traffic, and by the pg_cron jobs `enkop-master-drain` in both Supabase projects. Rows copied from the mirror set `enkop.skip_outbox = 'on'` for their transaction (`MasterStore.importRow`). SQL must use `?` placeholders and never the jsonb `?` operators.
- Schema changes must be made in both places: a Lovable migration in supabase/migrations and a matching master migration in master-db/migrations (applied with `node master-db/scripts/sql.mjs <file>`), plus the column list in src/server/backend/tables.ts. Content tables must stay column-for-column identical.
- Admin sign-in is ENKOP's own (master `admins`/`sessions`, lower-case emails, HttpOnly `enkop_admin` cookie, PBKDF2) and lives only on the master; /admin on Lovable hosting redirects there. Admin uploads go to `/api/admin/media` (50 MB), which stores them in the master's Storage bucket. New admins get a one-time link from cloudflare/scripts/admin-setup-link.mjs.
- Lovable is the fallback, never a second writer: on the master, `getBackend()` wraps the master database with `withMirrorFallback` (public reads from the mirror, enquiries stored in Lovable Cloud if the master fails), and cloudflare/entry.mjs serves the Lovable-hosted page when a public page fails (server functions only on 502–504; admin, media and `/api/public/enkop-*` never fall back). Enquiries stored on Lovable are pulled back by `pullMirrorEnquiries` (bridge `mirror/enquiries`) on every drain and alerted from the master.
- Alerts prefer Meta WhatsApp Cloud API (`META_WA_TOKEN`, `META_WA_PHONE_ID`, approved template `META_WA_TEMPLATE` with one body variable), then Lovable's WhatsApp connector via the bridge. Test with `node cloudflare/scripts/enkop-content.mjs test-alert`.
- AI-generated imagery is produced by the Cursor agent on request and uploaded with cloudflare/scripts/enkop-content.mjs (`upload`, `update`, `upsert`, `list`; `x-enkop-internal-key` against `/api/public/enkop-content/*`), so it goes through `MasterStore` and reaches the mirror like admin edits. The in-admin AI buttons remain on Lovable's gateway as the fallback.
- Provisioning lives in master-db/scripts (`provision.mjs`, `sql.mjs`), driven by a Supabase access token in %LOCALAPPDATA%\enkop-sync; secrets stay in that folder and are never printed or committed. Backend tests use PGlite (src/test/pg-db.ts) with the real master migration under `@vitest-environment node`.
- Deploying the master: `npm run deploy:cloudflare` (build, install `cloudflare/entry.mjs` as the Worker entry, `wrangler deploy --keep-vars`). The entry serves `/videos/*` with byte ranges because Workers Static Assets ignores Range and Safari needs 206 for video. Lovable's generated .output/server/wrangler.json is not used for the master.
- Homepage hero is a tour: HeroReel owns its parallax wrapper, a CSS push-in camera per scene and a walk-through leaving layer, with no on-screen controls (removed at the client's request). Because the tour cannot be paused, reduced-motion visitors get the first scene as a still image with no auto-advance.
- Company facts and positioning come from the ENKOP Real Estate company profile and live in src/lib/enkop.ts (`company`, `services`, `values`, `reasons`, `contact`, `enquiryInterests`); pages read from there rather than restating them. Copy stays confident and factual: no superlatives, rankings or claims the profile does not make. Enquiry links preselect the form topic with `/contact?interest=<one of enquiryInterests>`.
- Identity: royal blue (`--royal` #142B59) establishes the brand and premium gold (`--gold` #C6A45A) refines it, on warm ivory (`--ivory`), midnight (`--midnight`) and soft stone (`--stone`); tokens and their contrast notes are at the top of the ENKOP section of src/styles.css. Gold never carries text or essential icons on light surfaces (2.1:1); use `--gold-ink` there and `--gold`/`--gold-soft` only on royal, midnight or imagery. Selected states and focus are royal on light and soft gold on dark. Buttons use the `Button` variants `primary`, `premium` (viewing/enquiry), `line`, `onDark`, `textArrow` and `iconFrame` (classes `enkop-btn*`, `enkop-text-action`, `enkop-icon-frame`): 2px architectural corners, no pills, metallic gradients or glows. Editorial italics are royal on light and soft gold on dark. Seasons may tint `--background`/`--surface` and set `--season-glow`, but never override `--royal`, `--gold` or `--accent`; season particles fall continuously above page sections (z-index 40, below the header and gallery viewer, pointer-events none) and are cleared only from photos and videos.
- Brand: the ENKOP logo lives in public/brand (original JPG plus transparent cut-outs). Use the BrandLockup (building mark + ENKOP, auto-switching white/navy on dark/light headers) and BrandLogo (full stacked logo) components from src/components/enkop/BrandLogo.tsx instead of a text wordmark; favicon.ico, favicon-32.png, apple-touch-icon.png and brand/enkop-og.jpg are generated from the same artwork, recoloured to the brand royal blue and gold.
