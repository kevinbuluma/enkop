# Cloudflare Worker (master host) rules

- Admin sign-in is ENKOP's own (master `admins`/`sessions`, lower-case emails, HttpOnly `enkop_admin` cookie, PBKDF2) and lives only on the master; /admin on Lovable hosting redirects there. Admin uploads go to `/api/admin/media` (50 MB), which stores them in the master's Storage bucket. New admins get a one-time link from cloudflare/scripts/admin-setup-link.mjs.
- Alerts prefer Meta WhatsApp Cloud API (`META_WA_TOKEN`, `META_WA_PHONE_ID`, approved template `META_WA_TEMPLATE` with one body variable), then Lovable's WhatsApp connector via the bridge. Test with `node cloudflare/scripts/enkop-content.mjs test-alert`.
- AI-generated imagery is produced by the Cursor agent on request and uploaded with cloudflare/scripts/enkop-content.mjs (`upload`, `update`, `upsert`, `list`; `x-enkop-internal-key` against `/api/public/enkop-content/*`), so it goes through `MasterStore` and reaches the mirror like admin edits. The in-admin AI buttons remain on Lovable's gateway as the fallback.
- Deploying the master: `npm run deploy:cloudflare` (build, install `cloudflare/entry.mjs` as the Worker entry, `wrangler deploy --keep-vars`). The entry serves `/videos/*` with byte ranges because Workers Static Assets ignores Range and Safari needs 206 for video. Lovable's generated .output/server/wrangler.json is not used for the master. Security headers (HSTS, nosniff, X-Frame-Options, Referrer/Permissions-Policy) are added only in that entry, never via public/_headers, because Lovable's editor previews the site in a cross-origin frame. Canonical, og:url and share-image URLs come from `SITE_URL` / `pageSeo` in src/lib/enkop.ts (`https://enkoprealestate.com`). The Worker is attached as custom domains for the apex and `www` (wrangler `routes` with `custom_domain: true`); `cloudflare/entry.mjs` 301-redirects `www` and the `workers.dev` hostname to the apex.
